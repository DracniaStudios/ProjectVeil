## Summary

This week was almost entirely bug-fixing and internal engine hardening, plus one piece of new player-facing content
(the Tutorial Scene). No player-facing features shipped that require any action from players, and nothing here
changes save compatibility or controls layouts beyond the fixes noted below.

---

## New

- **Tutorial Scene.** Subject Veil now has a dedicated onboarding scene that plays before the main game, introducing
  the player to the core interaction and movement systems instead of dropping them straight into the world. It
  shipped with a build-breaking include and an unreachable-scene bug that briefly made it impossible to load; both
  were caught and fixed within a few days, so the scene is now reachable end-to-end. The UI header that used to say
  "UI" was also renamed to "UIEngine" as part of the same pass, which is a naming change only and not visible to
  players.

## Improved

- **Collision solver runs up to ~5x faster.** The physics broad phase used to walk the game's actual object
  containers directly, touching a full 896-byte GameObject to read the ~25 bytes it actually needed per pair check.
  It now copies just the bounding-box and flag data into a small, contiguous scratch buffer once per frame and scans
  that instead, which measured a 4.9x speedup on a representative level (1.33ms → 0.27ms per frame for the solver
  step). Players should see steadier frame pacing in scenes with a lot of interactables and physics bodies, with no
  change in which objects collide with which.
- **New allocator infrastructure (frame, growing-arena, slot-map, tracking).** This is foundational engine work, not
  a player-facing feature on its own: it adds a generation-tagged handle type (SlotMap) that makes stale references
  to destroyed entities fail safely instead of silently pointing at whatever object got reused in their place, plus
  debug-build memory poisoning that already caught one real bug during development. Players won't notice this
  directly, but it's the groundwork the last two weeks of crash fixes have been building toward.

## Fixed

- **The Stalker deals contact damage again.** A prior refactor that moved collision handling onto a new component
  type silently dropped the code that applied the Stalker's damage to the player on contact, with no compile error
  and no failing test to catch it — meaning the game's main threat had been harmless on touch for some time. Contact
  damage is restored and now has dedicated regression tests so this can't quietly break again.
- **Fixed a crash when interacting with artifact-unlock stations.** Unlocking an artifact could free the interactable
  object mid-interaction and then keep reading from it, a use-after-free that was reachable on every unlock
  interaction in the game. It's now fixed at the source so nothing touches the object again once it's been
  destroyed.
- **Fixed crashes in the Flappy Bird and Crane minigames.** Hitting an obstacle or going out of bounds in either
  minigame could free the minigame's data and then keep reading from it on the same frame, crashing the game. Both
  minigames now stop touching that data as soon as it's released.
- **Fixed extra, unintended gravity in the Flappy Bird minigame.** A leftover debug call was applying a second,
  smaller gravity impulse on top of the tuned one every frame, making the minigame feel noticeably heavier/faster
  than intended. It's been removed, so the minigame now plays at its designed difficulty.
- **Fixed UI buttons firing repeatedly while held down.** Holding the mouse button down on a UI button used to
  trigger its action once per frame for as long as it was held, instead of once per click. Buttons now correctly
  fire once on release.
- **Fixed a spurious fade transition over the main menu on every launch.** A leftover pointer from scene setup made
  the game think it needed to fade from the Tutorial scene into the main menu on startup, even when nothing had
  actually loaded yet. The main menu now appears cleanly on launch.
- **Fixed overlapping gamepad bindings.** On controller, the Interact and Move Left/Right actions silently shared
  buttons with a separate set of Artifact actions, so pressing one could unintentionally trigger the other. The
  Artifact actions have been moved to unused buttons, matching an equivalent fix already made for keyboard controls.
- **Fixed miscolored warning/header colors in the World Editor.** A handful of editor UI colors were being passed in
  the wrong numeric range and rendering far brighter than intended (an amber warning showing as pure yellow, a
  muted header showing as bright red). This only affects the in-editor developer tools, not gameplay.

## Breaking

- None this week. All changes above are bug fixes or internal performance/infrastructure work; no save data,
  control bindings (beyond the gamepad collision fix, which only frees up previously-conflicting buttons), or public
  behavior changed in an incompatible way.
