# Release Notes — Week of September 13–19, 2026

**Engine:** Veil

## Summary

A light week — three commits, no new systems. The headline is a Stalker balance change (base speed
2.0 → 5.0), alongside a round of bug fixes for a false coin jingle on every footstep, a double-firing
trigger event, a spurious fade over the main menu at launch, and a folder-deletion bug in the asset
scanner. No breaking changes.

---

## New

- **`GameObject::DrawGizmos()` hook.** Added an empty virtual `DrawGizmos()` to the `GameObject` base
  class. It does nothing yet, but it gives every object type a place to draw its own editor-only
  debug visuals (colliders, ranges, waypoints) without the World Editor needing to special-case each
  type. Nothing calls it yet, so there's no visible change this week — it's groundwork for editor
  tooling to build on.

## Improved

- **Stalker is more than twice as fast.** `Stalker::baseSpeed` went from `2.0` to `5.0` — a
  straightforward difficulty tuning pass rather than a systems change. Chases that used to give the
  player an easy lead now close much faster, so encounters that felt safely escapable before this
  build may not be anymore. Worth a look from anyone tuning route timing or safe-room placement
  around the Stalker.

## Fixed

- **Every footstep was playing a coin-pickup jingle.** `Player::EmitFootsteps` had a landing sound
  hardcoded onto regular walking footfalls, so ordinary walking triggered a "landing with coins" cue
  meant only for actual jumps. The hardcoded call is removed; footsteps now play their intended
  footstep audio and the landing jingle is reserved for landings.
- **Trigger volumes could fire `onTriggerEnter` twice on first contact.** `RigidBody3D::resolveConstrains`
  had two code paths both dispatching `onTriggerEnter` for the same trigger pair — one explicit call
  plus the id-based trigger-list dispatch below it. Anything listening for a single trigger event
  (a door, a pickup, a scripted sound cue) could double-fire on the frame contact begins. Removed the
  redundant explicit call; the id-based dispatch now fires it exactly once.
- **Main menu flashed a spurious fade transition on launch.** Scene startup had two code paths pushing
  the initial scene — a leftover `SceneManager_push` inside `SceneManager_init` racing with `gameMain`'s
  own push — so the main menu briefly faded as if transitioning to itself right after boot. The
  redundant push is removed; launch now goes straight to the main menu with no extra fade.
- **`AssetManager::loadFolder` was deleting scanned folders that had no direct files.** A recursive
  directory scan meant to record empty-of-files subfolders for bookkeeping instead called
  `std::remove(folder)` — the libc file-delete function, not the intended "add to list" call — so any
  scanned folder holding only subfolders (no files directly inside it) was deleted from disk during
  a scan. Replaced with the intended list bookkeeping; folders are recorded, not deleted.
- **Standalone `SoundField`/`Collider3D` test suite was broken and 5 of 6 suites in `tests/` didn't
  compile.** An added `SceneManager.h` include in `Collider3D.cpp` and an `AudioManager`-playing
  overload on `SoundField::Emit()` had quietly pulled full-engine dependencies into code documented as
  engine-independent, breaking the link for the standalone test target; separately, three test files
  still referenced a since-renamed `rigidBody3D.canCollide` field. Both dependency leaks are reverted
  (playback moved to the two real call sites, which already link the engine) and the test files are
  updated to `rigidBody3D.collider.canCollide`. `tests/run_tests.sh` now passes on all suites except
  `trigger_tests`, which fails for a pre-existing, unrelated reason (trigger dispatch was moved off
  virtual `GameObject` hooks in an earlier commit and never reconnected) and is flagged for a design
  decision rather than patched over.
